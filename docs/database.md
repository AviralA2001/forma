# Database Design

## Overview

PostgreSQL with JSONB for flexible, schema-variable data. Relational structure where relationships are clear, JSONB where schema flexibility is genuinely needed.

All tables have `created_at`. Tables with mutable data also have `updated_at`. All IDs are UUIDs generated by the database. Major tables have a `status` column for soft deletes — values are `active`, `inactive`, or `deleted`. No data is ever hard deleted.

---

## Core

### organisations
One row per company. Every piece of data in Forma is scoped to an organisation. The `domain` field restricts which email addresses can be added to the org.

```sql
CREATE TABLE organisations (
  org_id      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name        VARCHAR(255) NOT NULL,
  domain      VARCHAR(255) NOT NULL,
  -- e.g. 'company.com' — only emails from this domain can be added
  status      VARCHAR(20) DEFAULT 'active',
  -- active | inactive | deleted
  created_at  TIMESTAMP DEFAULT NOW(),
  updated_at  TIMESTAMP DEFAULT NOW()
);
```

---

### users
One row per person. Scoped to one organisation. Platform-level roles stored as a JSONB array. Project-level access is managed separately in `project_users`.

```sql
CREATE TABLE users (
  user_id       UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id        UUID NOT NULL REFERENCES organisations(org_id),
  name          VARCHAR(255) NOT NULL,
  email         VARCHAR(255) NOT NULL,
  is_site_admin BOOLEAN DEFAULT false,
  roles         JSONB DEFAULT '[]',
  -- platform level roles e.g. ["org_admin"] ["project_admin"] ["org_admin","project_admin"]
  -- valid values: org_admin, project_admin, project_user
  data          JSONB DEFAULT '{}',
  -- arbitrary columns from users CSV e.g. { manager_id, region, level }
  status        VARCHAR(20) DEFAULT 'active',
  -- active | inactive | deleted
  created_at    TIMESTAMP DEFAULT NOW(),
  updated_at    TIMESTAMP DEFAULT NOW(),
  UNIQUE(org_id, email)
);

CREATE INDEX idx_users_org_id ON users(org_id);
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_roles ON users USING GIN(roles);
```

---

### sessions
Magic link authentication. A token is created when the user requests a login link. Verified when they click it. Expires after a set duration.

```sql
CREATE TABLE sessions (
  session_id  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  token       VARCHAR(255) NOT NULL UNIQUE,
  expires_at  TIMESTAMP NOT NULL,
  created_at  TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_sessions_token ON sessions(token);
CREATE INDEX idx_sessions_user_id ON sessions(user_id);
```

## Projects

### projects
One row per workflow. Scoped to an organisation.

```sql
CREATE TABLE projects (
  project_id  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id      UUID NOT NULL REFERENCES organisations(org_id),
  name        VARCHAR(255) NOT NULL,
  status      VARCHAR(20) DEFAULT 'draft',
  -- draft | published | closed | deleted
  created_at  TIMESTAMP DEFAULT NOW(),
  updated_at  TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_projects_org_id ON projects(org_id);
```

---

### project_users
Maps users to projects with a specific role. A user can have multiple records for the same project if they hold multiple roles (e.g. both project_admin and project_user on the same project).

```sql
CREATE TABLE project_users (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id  UUID NOT NULL REFERENCES projects(project_id) ON DELETE CASCADE,
  user_id     UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  role        VARCHAR(30) NOT NULL,
  -- project_admin | project_user (only these two values allowed)
  status      VARCHAR(20) DEFAULT 'active',
  -- active | inactive | deleted
  created_at  TIMESTAMP DEFAULT NOW(),
  updated_at  TIMESTAMP DEFAULT NOW(),
  UNIQUE(project_id, user_id, role),
  CONSTRAINT valid_project_role CHECK (role IN ('project_admin', 'project_user'))
);

CREATE INDEX idx_project_users_project_id ON project_users(project_id);
CREATE INDEX idx_project_users_user_id ON project_users(user_id);
```

---

### tables
One row per uploaded CSV. Column definitions stored as JSONB since schema varies per file.

```sql
CREATE TABLE tables (
  table_id    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id  UUID NOT NULL REFERENCES projects(project_id) ON DELETE CASCADE,
  name        VARCHAR(255) NOT NULL,
  columns     JSONB NOT NULL DEFAULT '[]',
  -- [{ column_id, name, data_type: 'text' | 'number' }]
  status      VARCHAR(20) DEFAULT 'active',
  created_at  TIMESTAMP DEFAULT NOW(),
  updated_at  TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_tables_project_id ON tables(project_id);
```

---

### rows
One row per data row per uploaded table. All values in a flat JSONB map keyed by column_id. This is reference data only — salary bands, job families, lookup values. Not workflow records.

```sql
CREATE TABLE rows (
  row_id      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  table_id    UUID NOT NULL REFERENCES tables(table_id) ON DELETE CASCADE,
  data        JSONB NOT NULL DEFAULT '{}',
  -- { column_id: value }
  created_by  UUID REFERENCES users(user_id),
  status      VARCHAR(20) DEFAULT 'active',
  created_at  TIMESTAMP DEFAULT NOW(),
  updated_at  TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_rows_table_id ON rows(table_id);
```

---

### master_tables
Configuration only. No data lives here. Defines the shape of the published application — columns, joins, and routing rules. Formula definitions live in the columns JSONB.

```sql
CREATE TABLE master_tables (
  master_id   UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id  UUID NOT NULL REFERENCES projects(project_id) ON DELETE CASCADE,
  columns     JSONB NOT NULL DEFAULT '[]',
  joins       JSONB NOT NULL DEFAULT '[]',
  status      VARCHAR(20) DEFAULT 'active',
  created_at  TIMESTAMP DEFAULT NOW(),
  updated_at  TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_master_tables_project_id ON master_tables(project_id);
```

#### columns JSONB shape
```json
[
  {
    "column_id": "uuid",
    "name": "Job Role",
    "type": "lookup",
    "is_visible": true,
    "is_editable": true,
    "input_type": "dropdown",
    "lookup_table_id": "uuid",
    "lookup_column_id": "uuid"
  },
  {
    "column_id": "uuid",
    "name": "Base Midpoint",
    "type": "mapped",
    "is_visible": true,
    "is_editable": false,
    "source_table_id": "uuid",
    "source_column_id": "uuid"
  },
  {
    "column_id": "uuid",
    "name": "AY3 Mid",
    "type": "formula",
    "is_visible": true,
    "is_editable": false,
    "formula": "base_mid + (NHE * 25) + (AE * 50)"
  },
  {
    "column_id": "uuid",
    "name": "Base Actual",
    "type": "user_input",
    "is_visible": true,
    "is_editable": true,
    "input_type": "number"
  },
  {
    "column_id": "uuid",
    "name": "Next User",
    "type": "routing",
    "is_visible": false,
    "is_editable": false,
    "is_routing_column": true,
    "routing_source": "row_column | user_data_column",
    "routing_source_column": "column_id or user data key e.g. manager_id"
  }
]
```

#### Column types
| Type | Description |
|------|-------------|
| `mapped` | Pulled from a reference table row via a join |
| `formula` | Calculated at read time using Excel-compatible syntax. Never stored. |
| `user_input` | Filled in by the user. Stored in `master_rows.input_data` |
| `lookup` | Dropdown that triggers join resolution and auto-fills mapped columns |
| `routing` | Hidden. Holds next user_id. Drives row transfer on submission |

#### joins JSONB shape
```json
[
  {
    "base_table_id": "uuid",
    "join_table_id": "uuid",
    "on": {
      "base_column_id": "uuid",
      "join_column_id": "uuid"
    }
  }
]
```

### master_rows
One row per workflow record. These are the actual records users fill in and submit — one per offer, one per procurement request, etc. Only user_input column values are stored here. Mapped values are resolved from reference rows via joins. Formula values are computed at read time and never stored.

```sql
CREATE TABLE master_rows (
  master_row_id   UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  master_id       UUID NOT NULL REFERENCES master_tables(master_id) ON DELETE CASCADE,
  input_data      JSONB NOT NULL DEFAULT '{}',
  -- { column_id: value } for user_input columns only
  created_by      UUID REFERENCES users(user_id),
  status          VARCHAR(20) DEFAULT 'active',
  -- active | inactive | deleted
  created_at      TIMESTAMP DEFAULT NOW(),
  updated_at      TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_master_rows_master_id ON master_rows(master_id);
CREATE INDEX idx_master_rows_created_by ON master_rows(created_by);
```

## Access

### user_row_access
Controls which master rows each user can see and edit. Row ownership transfer for workflow routing is done by updating `user_id` on this record.

```sql
CREATE TABLE user_row_access (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  master_row_id   UUID NOT NULL REFERENCES master_rows(master_row_id) ON DELETE CASCADE,
  is_visible      BOOLEAN DEFAULT true,
  is_editable     BOOLEAN DEFAULT true,
  status          VARCHAR(20) DEFAULT 'active',
  created_at      TIMESTAMP DEFAULT NOW(),
  updated_at      TIMESTAMP DEFAULT NOW(),
  UNIQUE(user_id, master_row_id)
);

CREATE INDEX idx_user_row_access_user_id ON user_row_access(user_id);
CREATE INDEX idx_user_row_access_master_row_id ON user_row_access(master_row_id);
```

**Row transfer on submission:**
```sql
UPDATE user_row_access
SET user_id = 'new_user_id', updated_at = NOW()
WHERE master_row_id = 'row_xyz' AND user_id = 'old_user_id';
```

## Sub-tables

Admin-defined supplementary data attached to master rows. Schema defined now. UI and logic implemented at end of MVP.

### row_sub_tables
```sql
CREATE TABLE row_sub_tables (
  sub_table_id  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  master_id     UUID NOT NULL REFERENCES master_tables(master_id) ON DELETE CASCADE,
  name          VARCHAR(255) NOT NULL,
  columns       JSONB NOT NULL DEFAULT '[]',
  trigger       JSONB DEFAULT NULL,
  -- null if manually populated
  -- { on: 'row_transfer | action_button | manual', field_mappings: {} }
  status        VARCHAR(20) DEFAULT 'active',
  created_at    TIMESTAMP DEFAULT NOW(),
  updated_at    TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_row_sub_tables_master_id ON row_sub_tables(master_id);
```

---

### row_sub_table_entries
```sql
CREATE TABLE row_sub_table_entries (
  entry_id        UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  sub_table_id    UUID NOT NULL REFERENCES row_sub_tables(sub_table_id) ON DELETE CASCADE,
  master_row_id   UUID NOT NULL REFERENCES master_rows(master_row_id) ON DELETE CASCADE,
  sequence        INTEGER NOT NULL,

  created_by      VARCHAR(50) NOT NULL,
  -- user_id or 'system'
  created_at      TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_sub_table_entries_sub_table_id ON row_sub_table_entries(sub_table_id);
CREATE INDEX idx_sub_table_entries_master_row_id ON row_sub_table_entries(master_row_id);
```

### audit_logs
Append-only. Never updated or deleted.

```sql
CREATE TABLE audit_logs (
  audit_id      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id        UUID NOT NULL REFERENCES organisations(org_id),
  project_id    UUID REFERENCES projects(project_id),
  user_id       UUID REFERENCES users(user_id),
  action        VARCHAR(100) NOT NULL,

  entity_id     UUID,
  old_value     JSONB,
  new_value     JSONB,

);

CREATE INDEX idx_audit_logs_org_id ON audit_logs(org_id);
CREATE INDEX idx_audit_logs_project_id ON audit_logs(project_id);
CREATE INDEX idx_audit_logs_entity_id ON audit_logs(entity_id);
```

### notifications
```sql
CREATE TABLE notifications (
  notification_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
```

## Table Creation Order

Follow this exact order to avoid foreign key dependency errors:

1. `organisations`
2. `users`
3. `sessions`
4. `projects`
5. `project_users`
6. `tables`
7. `rows`
8. `master_tables`
9. `master_rows`
10. `user_row_access`
11. `row_sub_tables`
12. `row_sub_table_entries`
13. `comments`
14. `audit_logs`
15. `notifications`

## Key Design Decisions

**Calculated columns are never stored.** Formula columns are evaluated at read time. Only user_input values are stored in `master_rows.input_data`.

**Reference data and workflow data are separate.** `rows` holds CSV reference data. `master_rows` holds workflow records. They never mix.

**Roles live in two places for two purposes.** Platform-level roles (org_admin, project_admin, project_user) live as a JSONB array on `users`. Project-level access and role within a specific project lives in `project_users`. Both are needed.

**One project role per record.** `project_users` allows multiple records per user per project (one per role) with a unique constraint on project_id + user_id + role. Only `project_admin` and `project_user` are valid values.

**Org admin has no project access.** Org admin manages users and org settings only. They do not appear in `project_users` unless explicitly added as a project_admin or project_user.

**Soft deletes everywhere.** Major tables have a `status` column with values `active`, `inactive`, or `deleted`. Nothing is ever hard deleted. All queries filter `WHERE status != 'deleted'`.

**Row ownership is a transfer.** When a row moves from one user to another, `user_row_access.user_id` is updated. The master row itself never moves.

**Tenant domain restriction.** Users can only be added to an organisation if their email domain matches `organisations.domain`.

**Audit log is append-only.** No updates, no deletes. Ever.
